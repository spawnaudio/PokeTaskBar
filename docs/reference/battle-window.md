# Battle window

PokeTasks v2.5 adds a second floating-pet style. In Settings → Desktop, enable the floating pet and choose **Battle window**. Classic remains the default.

HP counts down remaining time. HP and XP have equal tracks, with no visible XP percentage. Pause freezes the clock and sprite movement and mutes the window. Zero HP waits for a choice.

- **Complete** completes the task through the existing completion and reward rules. Local tasks stay local; Linear tasks must complete successfully before settling.
- **Potions** opens the bag, where using an item consumes one owned potion and adds its full effect. A paused timer stays paused; a timer at zero resumes. The total cap is 180 minutes.
- **Forfeit** cancels the timer and pending session XP. Previously earned XP and the unfinished task remain.

The bag offers Potion (+5 minutes), Super Potion (+15), Hyper Potion (+30), Revive (+60), and Full Restore (custom whole minutes). Single-click selects an item; double-click uses the clicked potion. Full Restore first asks for custom minutes. Empty items and boosts above the time limit cannot be used, and shop double-clicks do not buy or use items. The shop uses the existing Coins wallet and difficulty-adjusted prices. An interrupted potion save recovers as paused on restart without spending the same item twice.

**Choose task** on the idle screen, or under More during a session, opens a searchable list of open Linear issues inside the Battle panel. It uses the same native issue cards, metadata, expansion and focus-duration controls as the task workspace. Selecting another task preserves the current timer until the existing forfeit confirmation is accepted; closing the chooser cancels the switch. The chooser follows Battle’s scale and keeps screen-edge tucking suspended while open.

Drag the header to move the window. More contains pin, screen-edge tuck and Choose task. Settings → Desktop shows one **Battle window scale** slider (50–200%) that scales the entire frame, artwork, bars, buttons and menus together. Its saved scale and position are independent of Classic's pet/timer sizes; upgrading preserves the former Battle scale. Animation respects reduced motion. Pokémon and item sprites download into the existing runtime cache; the bundle includes original UI artwork and the licensed Departure Mono pixel font. Departure Mono uses 11 px steps for headings, Pokémon names, HP/XP labels and the countdown; a system monospace (Menlo on macOS) handles instructions, controls, menus and item details. Longer countdowns use a smaller pixel size to keep the planned duration legible.

The header's **−** button folds Battle into an original pixel Game Boy icon. Its LCD shows the same live countdown while a timer is active, freezes and dims when paused, and shows 0:00 while awaiting a choice. Click the icon to unfold the same Battle view; drag it to move, or right-click → **Tuck at screen edge**. Half of the icon peeks from the nearest edge with an inward 12° tilt. Hover reveals the upright icon; leaving retucks it after 350 ms. Folding survives restart, follows the Battle scale, and leaves the native timer and rewards running. The hidden web view suspends updates and retains its current menu and input state for unfolding. Classic's timer folding stays independent.

The React source is in `BattleWindowWeb`. Run `npm ci && npm run build` there to update the offline UI, then `PTB_SKIP_INSTALL=1 bash scripts/rebuild-v3.sh` at the repository root to build PokeTasks v3 (3.0.0). Generated resources are committed so normal Swift builds and CI do not require Node. `BattleWindow` hosts the local UI in the existing floating panel; Swift owns every timer and inventory action.

The v3 builder retains the v2.5 bundle identifier for settings and credentials, and sets `PTBStateFolderName` to `PokeTasks v2.5` for existing saves. The app name is PokeTasks v3 and the menu bar window/header title is PokeTasks. Run only one version at a time because both share that profile. It uses the existing `assets/PokeBall.icns` icon.

V3 requires a valid `PokeTaskBar Local` signing identity instead of falling back to ad-hoc signing. Run `bash scripts/create-signing-cert.sh` once if that identity is missing; its certificate and private key stay in the local login keychain. This local development build uses macOS Open at Login, because macOS rejects the locally signed managed agent's launch constraint. An enabled previous agent is migrated by registering and verifying Open at Login is enabled before removing the agent. Local builds launch at login without the agent's crash watchdog; distribution builds retain the bundled watchdog and use `BundleProgram` to resolve its executable within the signed app.

Right-click the Battle window, folded Game Boy, Classic pet or floating timer to choose **Battle Window Mode**, **Classic Floating Pet Mode** or **Floating Timer Only Mode**. The active mode has a checkmark. Switching displays preserves the running or paused focus session. Timer Only keeps a start surface visible when idle, including after relaunch, so its menu remains available. The same menu has live size sliders: Battle/Game Boy scale (50–200%), Classic pet size (48–384 px) and floating timer scale (50–200%). Each size is saved independently; Settings uses the same values.
